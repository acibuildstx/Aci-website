## Inspected

Both HTML pages; all browser JavaScript, styles and logo; all seven original Pages Functions; SQL schema; Wrangler configuration; setup documentation; and all 60 packaged WebP photographs. Checked local asset links, navigation targets, gallery configuration, error states, uploads, private media, owner authorization, database writes and email handling. `INSPECTION-MANIFEST.json` inventories every original file and its before/after hash.

## Repaired

| Area | Verified defect and resulting behavior |
| --- | --- |
| Owner security | APIs originally trusted that Access would be configured externally, without checking authentication. Middleware now verifies signed Access JWTs, issuer, audience, expiry and an owner email allowlist; both `/admin` and `/admin.html`, owner APIs and customer media fail closed. Cookie JWT verification also supports draft image previews. |
| Customer privacy | Expiring links alone originally granted access. Attachments now require owner sign-in as well as a valid, unexpired token. Responses download files with encoded filenames, no caching and no MIME sniffing. No route exposes original photo backups. |
| Injection & request safety | Escaped stored category names, captions, attachment filenames and email HTML. Restricted image URLs to application paths. Added CSP/security headers, cross-site mutation rejection, required-field/length/type validation and a shared D1 limit of five submissions per IP-derived counter per ten-minute window. Provider/database details are not sent to visitors. |
| Uploads & persistence | Validate every attachment before writing any object, check supported MIME signatures and sizes, cap aggregate attachments at 30MB (25MB/file, five files). Save inquiry, attachment tokens and notification record in one D1 transaction; attempt R2 cleanup on storage failure. Owner uploads reject invalid WebP/conversion failures and roll back partial writes. Removed data-URL fallback that falsely implied remote upload success. |
| Email correctness | Requests remain saved when Resend is missing or fails. Track `pending`, `failed` or `accepted` in D1 with provider ID when available. The form explicitly warns on failed/unconfirmed notification and gives the saved reference. A successful Resend API response is called **accepted**, never delivered. Escape email content, use a timeout and provider idempotency key. Removed test-sender fallback. |
| Gallery | Atomic draft/published saves; validate save modes, unique slugs and media paths. An intentionally empty/all-hidden published gallery no longer reverts to starter images. Hidden categories are omitted from public responses. Draft R2 uploads require owner authorization until referenced by the published gallery. Save/upload failures stay visible. Photo order, cover, hero and before/after controls retain their original design. |
| Navigation & mobile | Preserved branding, colors, typography, wording and smooth scrolling except necessary upload-limit/status accuracy. Added narrow-screen overflow fixes, wrapped intermediate-width navigation, sticky-header anchor spacing, keyboard photo activation and lightbox focus handling. Existing images and design tokens are byte-for-byte unchanged. |
| Tooling/config | Added pinned dependencies, lockfile, build/test scripts, explicit Pages routing, private-file exclusions and additive SQL tables. Upgraded Wrangler to address development dependency advisories; final npm audit reports zero known vulnerabilities. |

## Content and functional limitations requiring owner attention

- **Photograph review:** many `cover.webp` files duplicate `1.webp`; some photographs also repeat across categories. Several captions describe finished work while the supplied image shows construction, and some descriptions appear mismatched. Preserve the supplied photos/copy until the owner confirms selection, captions, rights and attribution; photographic provenance and claimed experience were not independently verified.
- **Empty slots:** Roofing, Custom Installations and Exterior & Siding have no photographs and remain hidden. No fabricated photos or before/after pairs were added. Before/after functionality works when an owner supplies a genuine pair.
- **Gallery scope:** the approved public design displays the first three photos per category; additional uploaded/packaged photos are an archive, not a public browse-all feature. “Preview Site” opens the published site, not a separate draft preview. Deleting a photo removes its gallery reference; it does not erase its R2 original or optimized object. No trash/restore UI is included.
- **Operations:** this owner portal manages the gallery, not an inquiry inbox. Inquiries and failed/pending notification records can be reviewed in the authenticated D1 console using the checklist query. There is no automatic notification retry, bounce/delivery webhook, customer receipt or scheduled cleanup. Monitor and handle failed/pending notifications manually. `accepted` never confirms inbox delivery.
- **Retention/abuse:** links expire after 14 days; expiry does not delete files or customer records. Configure retention/lifecycle before launch. Cleanup attempts cannot guarantee removal after process termination; review orphaned uploads. Signature checks are not malware scanning. D1 rate limiting/honeypot are basic abuse controls, not comprehensive bot protection; shared-network users can hit the same limit.
- **External configuration:** actual D1/R2 resources, Access policy coverage, chosen hostname support, sender-domain verification and live mail delivery were not verified without accounts. Test maximum-size mobile uploads and real HEIC/MOV variants on intended devices; browser conversion depends on decoder support. Free-tier capacity, billing enrollment and current provider quotas require owner confirmation. Google Fonts remains an external dependency.
